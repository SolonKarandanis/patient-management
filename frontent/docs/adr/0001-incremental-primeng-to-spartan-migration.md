# Incremental PrimeNG → spartan-ng migration

We're replacing PrimeNG with spartan-ng because PrimeTek archived the PrimeNG repo (2026-06-29) and moved future major versions to a commercial license (~$599/developer); our installed v21.0.2 stays MIT forever, but we get no free upgrades past it. We chose to migrate incrementally — both libraries installed side by side, migrated domain by domain — rather than a single big-bang cutover, because the surface area is large (27 files import PrimeNG across 21 distinct modules, PrimeNG services are injected outside components in `role.guard.ts`/`error.service.ts`/`util.service.ts`, and `results-table` wraps a server-side lazy-paginated data grid). A big-bang branch would block every other change on the hardest single piece and risk a long-lived, hard-to-rebase branch.

## Consequences

- `primeng` and `@spartan-ng/*` (or whichever spartan packages we land on) will coexist in `package.json` for the duration of the migration, and both libraries' CSS/JS ship to the browser until it's complete.
- Cutover is checklist-based, not deadline-based: PrimeNG is removed once `grep -r "from 'primeng"` across `src` returns zero hits, `ToastService`/`ConfirmService` (see [ADR-0002](./0002-notification-confirm-facade-services.md)) have fully replaced `MessageService`/`ConfirmationService`, `results-table` is rebuilt (see [ADR-0003](./0003-results-table-on-spartan-data-table.md)), `providePrimeNG`/`Aura` is deleted from `app.config.ts`, the `primeicons.css` import and the leftover `::ng-deep .p-select-label` override are removed from `styles.css`, and `primeng`/`@primeng/themes`/`primeicons` are removed from `package.json`, and `angular.json`'s initial bundle `maximumError` budget is restored from `2MB` back to `1MB` (raised temporarily during coexistence — both libraries shipping at once pushed the initial bundle from 968kB to 1.05MB, over the original error threshold). We chose this over a hard calendar deadline because forcing the two hardest pieces (the facade, `results-table`) under time pressure would undercut the reason we chose incremental migration in the first place.

## Progress

**Migration complete as of 2026-08-11.** `grep -rn "from 'primeng"` across `src` returns zero hits (excluding none — even the `SelectItem` type alias is gone, replaced by a local `@models/select-item.model.ts`). `primeng`/`@primeng/themes`/`primeicons` are removed from `package.json` and `node_modules` (`npm install` ran clean, no orphaned peer deps). `providePrimeNG`/`Aura` removed from `app.config.ts`, `PrimeNG` config injection and `primengConfig.ripple.set(true)` removed from `app.component.ts`. `primeicons.css` import and the `::ng-deep .p-select-label` override removed from `styles.css` (confirmed safe first: repo-wide grep for `pi pi-`/`pi-` classes returned zero hits — the only `SearchTableColumn` config in the app, `getSearchUserTableColumns()`, never used the `icon`/`headerIcon` fields). `angular.json` initial bundle `maximumError` restored to `1MB`; actual initial bundle is now 861.76 kB (down from ~1.17 MB with both libraries coexisting) — still over the pre-existing 500kB `maximumWarning` (that warning predates this migration, per the "968kB" figure in Consequences above; not something this ADR is scoped to fix).
